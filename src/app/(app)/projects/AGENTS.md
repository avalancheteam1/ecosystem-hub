# Projects

Rules for this area. The root `AGENTS.md` applies too.

## Projects (`src/app/(app)/projects/`)
- Builder-owned, team via `ProjectMember` (one owner) + email invites (`ProjectInvite`, token hashed, 14 days, accepted only by the invited verified email; re-inviting a member is refused - never downgrades). Invites from a hackathon's find-a-team list go **by user id** instead (`inviteeUserId` set, `email` null): the address is never stored on the invite or shown to the owner (the team panel shows the name), and only that user can accept (`joinViaInvite`, `acceptInviteById`, `listMyInvites` match the user id).
- **Roles** (`PROJECT_ROLES` in `_lib/rules.ts`): `reader` views · `writer` + edits, milestones, uploads, submits/withdraws · `owner` (one) + invites, revokes, sets roles, removes, transfers. Deny someone else's project with `ForbiddenError`. Readers are **not** on the hackathon team (size, join, snapshot, one-submission clash - filter `role: { in: TEAM_ROLES }`) but still count for judges' COI.
- **Draft + sealed versions.** `Project.currentVersionId` points at the latest `ProjectVersion`. While it is a **draft** (`sealedAt` null) edits update it in place (`planSave`); builders don't see edit history. **Submitting seals it** (`planSeal`, inside the submission transaction: `sealedAt` + note "Submitted to …") and the stage entry pins it; the next edit starts a new draft (number + 1). Re-submitting without changes reuses the sealed version. **Sealed rows are immutable** - never update or delete them. Writers can also seal the draft by hand (`sealVersion`, "Save as version", note required). A submission-sealed version that no stage entry points at any more was re-submitted with a later one (`wasReplaced`, keyed on the `submissionNote` prefix) and is labelled "replaced".
- Fields follow builders-hub's battle-tested submission set (`_lib/rules.ts`: categories, tech stack defaults, limits, link normalisation) - but stored as real arrays. `missingForSubmission` = builders-hub's "complete" set, except that the main website (`websiteUrl`) can replace the demo link; hackathon submission requires it.
- **Project stage** (`ProjectVersion.maturity`, required on save and in `missingForSubmission`; null only on versions saved before it existed): idea → prototype → MVP → testnet/beta → live → established, keys in `src/lib/project-maturity.ts` (only add). Versioned like every field, so a submission shows the stage it was judged at.
- **Version history:** the project page lists each version's `ProjectActivity` rows (submitted to a hackathon, approved on Developer Tooling, withdrawn, replaced, …), newest first, each linking to where it happened (`activityHref`). Team members appear by name, reviewers and organisers as the program's staff ("team1", "the organisers"), internal reasons never: read it only through `listProjectActivityForTeam` (`_lib/queries.ts`), which applies `teamActivityView` before returning, so no internal reason or staff id reaches a page or client component. `getProjectForMember` doesn't load activity. Versions without activity show their seal note. Backfilled from stage entries and tooling audit entries (migration `project_activity`): a hackathon entry's earlier versions weren't kept, so only the version it holds now has its "submitted" row.
- Rendering a version: `ProjectVersionView` (`src/components/`), shared by project, organiser and judge pages.
