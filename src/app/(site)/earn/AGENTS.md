# Earn

- The default-off `earn` flag controls public routes, public links, sitemap entries and contributor actions. Staff can prepare and manage bounties in `/admin/earn` while the flag is off.
- The public catalog and brief read published rows through server-only queries. Use explicit field projections, apply visibility before pagination, and keep deadlines in UTC.
- Admin deadline fields are entered in UTC.
- Central team1 publishes through `/admin/earn`. Grant `earn.publish` only to designated staff. Review pages and actions require `earn.review`, and private final selection also requires `earn.finalize`. Only a Hub super admin can cancel a public listing or announce results. Never use Portal membership to grant Hub staff access.
- Drafts and receipts are private. Put object and owner checks on writes and reads. Participant projections never select internal notes. Private final-stage approval and its feedback stay hidden until announcement.
- Serialize cross-row state decisions by locking the bounty row inside the transaction. Check submission version, stage gate, deadline and terms version on the server. Append revision evidence and decision history, and write audit metadata in the same transaction. Use the Hub rate limiter on contributor writes. Do not log work evidence or private notes in audit metadata.
- Every new later-stage submission links to an approved entry from the same contributor and the immediately previous saved stage on the same bounty, including bounties that previously allowed parallel submissions. The first stage has no parent. Under the bounty lock each parent can have one linked continuation in pending, needs review, changes requested or approved. Rejected and withdrawn entries free the slot. Revisions preserve recorded links. Legacy unlinked receipts remain readable without inferred predecessors.
- Published briefs can be edited live until cancellation or announcement. Before any submission, retain saved stage IDs and explicitly confirm removals with `removedStageIds` in a stage save. After any submission, including withdrawn or rejected work, stage identity, order and requirements are locked. A published brief can be taken offline only before it receives work. Cancellation closes the listing and keeps contributor receipts and staff history.
- Effective additional terms can change on a live brief. A real change increments the terms version and keeps previous acceptance history. New submissions and revisions still require consent to the current version. Native publication and live native saves require approved effective terms while the official default copy is pending.
- Only the final stage produces awards, once announced. Finalizers can undo an unpublished selection with a private reason.
- GitHub references are manually verified. Public briefs may contain only GitHub issue links cleared for public sharing. Pull requests in contributor receipts stay private.
- Members-only opportunities run in the Member Portal. The Hub records external reward declarations and never executes payment or writes XP.
